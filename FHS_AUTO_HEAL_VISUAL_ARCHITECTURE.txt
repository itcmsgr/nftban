                    SECURITY BOUNDARY ENFORCEMENT

┌─────────────────────────────────────────────────────────────────────────┐
│                          ATTACKER SCENARIOS                             │
└─────────────────────────────────────────────────────────────────────────┘

Scenario 1: Compromise nftban user
    ↓
Attacker tries: echo "malicious" > /usr/lib/nftban/core/module.sh
    ↓
Result: ❌ BLOCKED (owner: root, not writable by nftban)
    ↓
Security: ✅ System code protected


Scenario 2: Compromise nftban user, modify owned files
    ↓
Attacker tries: echo "malicious" > /var/lib/nftban/data.txt
    ↓
Result: ✅ SUCCEEDS (nftban owns it)
    ↓
Impact: Limited to runtime data only (not system code)
    ↓
Security: ✅ Blast radius contained


Scenario 3: Try to escalate privileges
    ↓
Attacker tries: chmod u+s /usr/sbin/nftban
    ↓
Result: ❌ BLOCKED (owner: root, nftban can't change perms)
    ↓
Security: ✅ No privilege escalation possible
