Fail2ban Configuration Hierarchy
Fail2ban loads configuration files in this order (later files override earlier ones):
/etc/fail2ban/jail.conf (DO NOT EDIT - this is the default config)
/etc/fail2ban/jail.d/*.conf (.conf files in this directory)
/etc/fail2ban/jail.local (if exists)
/etc/fail2ban/jail.d/*.local (.local files in this directory)

Current Hierarchy example sample : 
/etc/fail2ban/jail.d/
├── 00-defaults.conf                      # Global settings
├── 100-nftban-system-sshd.conf           # SSH jail
├── 200-nftban-web-nginx.conf             # Nginx jails
├── 300-nftban-appl-wordpress.conf        # WordPress protection
├── 400-nftban-future-use-range.conf      # Future  protection
└── 500-nftban-custom.conf                # Custom jails by user


You don't need jail.local - you can use the jail.d/ directory instead.

Why we use jail.d/ instead of jail.local
- Modularity: Separate files for different services
- Easier Management: Enable/disable services by moving files
- Version Control: Track changes to individual services
- Less Error-Prone: Mistakes affect only one service
- Clear Organization: Know exactly what each file does
- Files are loaded in alphabetical order (use numbers for ordering)
- Later files override earlier ones in case of conflicts


Complete Working Example
- Here's how to set it up properly:

Step 1: Remove or backup old jail.local (if exists)
bash
sudo mv /etc/fail2ban/jail.local /etc/fail2ban/jail.local.backup
Step 2: Create individual configuration files
/etc/fail2ban/jail.d/00-defaults.conf (global settings):

ini
[DEFAULT]
# Global settings
bantime = 3600
findtime = 600
maxretry = 3
destemail = admin@example.com
sender = fail2ban@example.com

# Ignore local IPs
ignoreip = 127.0.0.1/8 ::1 192.168.0.0/16 10.0.0.0/8
/etc/fail2ban/jail.d/10-sshd.conf (SSH protection):

ini
[sshd]
enabled = true
port = ssh
logpath = %(sshd_log)s
maxretry = 3
bantime = 86400

action = %(action_)s
         advanced-email[
             destemail="security@example.com",
             notify_ban=true,
             notify_unban=true,
             include_whois=true,
             include_nslookup=true
         ]
/etc/fail2ban/jail.d/20-nginx.conf (Web protection):

ini
[nginx-http-auth]
enabled = true
port = http,https
logpath = /var/log/nginx/error.log
maxretry = 3

[nginx-badbots]
enabled = true
port = http,https
logpath = /var/log/nginx/access.log
maxretry = 2
bantime = 3600

action = %(action_)s
         advanced-email[
             destemail="webmaster@example.com",
             notify_ban=true
         ]
Step 3: Verify and Test
bash
# Check configuration syntax
sudo fail2ban-client -t

# Reload fail2ban
sudo systemctl reload fail2ban

# Check enabled jails
sudo fail2ban-client status

# Check specific jail configuration
sudo fail2ban-client get sshd action
File Naming Convention in jail.d/
Use numbers to control load order:

00-*.conf - Default settings
10-*.conf - Core services (SSH, etc.)
20-*.conf - Web services
30-*.conf - Database services
40-*.conf - Custom services

How to Enable/Disable Jails
To disable a jail:

# Method 1: Remove the config file
mv /etc/fail2ban/jail.d/10-sshd.conf /etc/fail2ban/jail.d/10-sshd.conf.disabled

# Method 2: Comment out in the file
# enabled = false

# Reload to apply changes
sudo systemctl reload fail2ban

To enable a jail:
# Method 1: Restore the config file
sudo mv /etc/fail2ban/jail.d/10-sshd.conf.disabled /etc/fail2ban/jail.d/10-sshd.conf

# Method 2: Set enabled = true
# enabled = true

# Reload to apply changes
sudo systemctl reload fail2ban
